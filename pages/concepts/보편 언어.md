## 한 줄 정의

> 🟡 **개발에 참여하는 모든 사람이 도메인 모델에 기반한 단일 어휘 체계를 만들고, 문서·회의·대화 그리고 코드에까지 일관되게 쓰는 것.** Ubiquitous Language.

## 왜 필요한가

같은 개념에 서로 다른 용어를 쓰거나, 두루뭉실하게 써서 받는 쪽이 전혀 다르게 이해하는 일이 현장에서 매우 흔하다. 그 비용은 회의 시간이 아니라 **잘못 만든 기능**으로 돌아온다.

> 🔴 **프로젝트 초에 용어집 하나 만들어 두고 "필요하면 참고하세요"는 실패하는 전형이다.** 그 뒤 대화도 코딩도 각자 원래 쓰던 말로 돌아간다. **의식적인 노력**이 필요하다.

## 어떻게 동작하는가

핵심은 **"코드에까지"** 다. 회의에서 "심사 반려"라고 부르는 것이 코드에서 `updateStatus(2)`이면 보편 언어가 아니다.

```java
// 보편 언어가 코드에 없는 상태
member.setStatus(MemberStatus.ACTIVE);
if (member.getStatus() == MemberStatus.ACTIVE) { ... }

// 도메인의 말이 그대로 남은 상태
member.activate();
if (member.isActive()) { ... }
```

> 🟢 기술에도 보편 언어가 필요하다. 헥사고날의 중심 육각형을 팀이 "헥사곤"이라 부를지 "애플리케이션"이라 부를지 **하나로 정해 두는 것**도 같은 실천이다.

## 코드에 닿는 지점

프로젝트에 남기는 **용어 사전** — 한국어 표현 ↔ 영어 표기 ↔ 정확한 정의. 목적은 "그 단어를 들으면 모두가 같은 그림을 떠올리게" 하는 것이다.

인터페이스 이름도 대상이다. 🟢 `PasswordEncoder`의 파라미터를 도메인 언어(`plainText`, `passwordHash`)로 두고 스프링 시큐리티 용어(`rawPassword`, `encodedPassword`)는 어댑터 안에 가두면, 도메인 쪽 코드가 기술 용어를 배우지 않아도 된다.

## 트레이드오프

| 유지 비용을 낼 때 | 안 낼 때 |
|---|---|
| 도메인 전문가와 계속 대화해야 할 때 | 용어가 이미 업계 표준이라 흔들릴 일이 없을 때 |
| 팀이 크거나 사람이 자주 바뀔 때 | 혼자 짧게 만들 때 |

대가는 **꾸준함**이다. 이름은 한 번에 완벽하게 지어지지 않고, 시간이 지나며 의도를 더 잘 드러내는 쪽으로 바꿔 나가는 것이다. 그 리네이밍 비용을 계속 낼 각오가 없으면 용어집은 죽는다.
