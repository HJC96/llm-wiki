## 한 줄 정의

🟡 **서비스 하나가 자기 트랜잭션을 성공적으로 끝냈는데, 전체 흐름은 실패한 상태.** 되돌리라는 신호를 받을 통로 자체가 없다.

## 왜 필요한가

[[2PC]]·[[TCC]]·[[Saga 패턴]]이 푸는 문제가 정확히 이것이다. 이 상태를 먼저 이해하지 않으면 세 기법이 왜 필요한지가 안 보인다.

## 어떻게 동작하는가

```java
@Transactional
public long reserve(long requestId, long workshopId, int seatCount) {
    // ...
    return amount;   // ← 응답을 보내기 전에 이미 커밋된다
}
```

🟡 **HTTP 호출은 같은 트랜잭션에 참여하지 않는다.** 호출한 쪽이 자기 트랜잭션 안에서 불러도, 호출당한 서비스는 **자신의 트랜잭션을 시작하고 응답 전에 커밋**한다.

🟢 [[분산 트랜잭션 기준선 - MSA]]가 이걸 재현한다 — 좌석 커밋 후 지갑이 실패하면 좌석은 **이미 커밋됐고 되돌릴 수단이 없다.** 모놀리식에서 `ROLLBACK` 한 줄이던 것이 여기서는 아무것도 되돌리지 못한다.

## 코드에 닿는 지점

```text
Reservation @Transactional → reservation_db
Seat        @Transactional → seat_db     ← 각자 자기 DB만
Wallet      @Transactional → wallet_db
```

🔴 `@Transactional`을 코디네이터 메서드에 붙여도 소용없다. 오히려 [[Saga 패턴]]에서는 `try-catch`로 보상을 돌리다 롤백 신호를 삼켜 **더 나쁜 상태**를 만든다.

## 트레이드오프

이건 고르는 게 아니라 **감수하거나 막는 것**이다.

| 접근 | 부분 커밋을 |
|---|---|
| [[2PC]] | **애초에 못 생기게** 한다 (대가: 블로킹) |
| [[TCC]] | 생기되 "예약" 상태라 **외부에 안 보인다** |
| [[Saga 패턴]] | 생기는 걸 허용하고 **보상으로 되돌린다** |

🔴 **아무 대책 없이 서비스를 나누면 부분 커밋은 반드시 생긴다.** "아직 문제가 안 생겼다"는 트래픽이 적다는 뜻이지 안전하다는 뜻이 아니다.

🔴 네트워크 실패까지 겹치면 더 나빠진다 — 타임아웃은 **"실패"가 아니라 "알 수 없음"**이라, 상대가 커밋했는지조차 모른다 → [[멱등성]]
