## 한 줄 정의

> 🟡 **블로킹/논블로킹은 "호출한 스레드가 멈추느냐"이고, 동기/비동기는 "결과를 내가 이어서 처리하느냐, 콜백을 넘기느냐"다.** 두 축은 독립이라 네 조합이 나온다.

## 왜 필요한가

이 둘을 한 축으로 합쳐 놓으면 "WebFlux 코드가 위에서 아래로 순서대로 읽히니까 동기 아닌가"라는 질문에 답할 수 없다. 코드가 순차적으로 **읽히는 것**은 실행 순서를 선언한 것일 뿐이고, 실제 실행은 값이 도착하는 미래 시점에 일어난다.

## 어떻게 동작하는가

| | 블로킹 | 논블로킹 |
|---|---|---|
| **동기** | Spring MVC + JDBC | 드물다. 결과 없으면 즉시 리턴받고 **내가 계속 폴링** |
| **비동기** | `@Async` + JDBC (콜백은 넘기지만 내부 스레드는 블로킹) | **WebFlux / Reactor** |

> 🟢 **동기 논블로킹은 애플리케이션 레벨에서 거의 안 쓴다.** 쓰이는 자리는 셋이다 — ① 이벤트 루프 내부 구현(Netty·nginx가 `epoll`/`kqueue`로, Java NIO `Selector` + `configureBlocking(false)`), ② "일단 시도, 없으면 나중에" 패턴(`queue.poll()`, `tryLock()`, `SocketChannel.read()`가 0 리턴), ③ 폴링이 자연스러운 상황(센서 레지스터, 게임 루프).

애플리케이션에서 안 쓰는 이유는 명확하다. 동기 논블로킹은 결과가 없으면 **내가 계속 다시 물어봐야** 하므로 CPU 낭비이거나 지연이다. 그래서 그 위에 비동기(이벤트 통지)를 씌워 "준비되면 알려줘"로 바꾼다. 우리가 만지는 건 대부분 **동기 블로킹**(MVC+JDBC) 아니면 **비동기 논블로킹**(WebFlux)이다.

> 🔴 `@Async` + JDBC를 "논블로킹"이라고 부르면 틀린다. 호출자는 안 막히지만 **작업 스레드는 그대로 소켓 앞에 서 있다.** 스레드를 옮겼을 뿐 총 점유량은 그대로다.

## 코드에 닿는 지점

```java
// 동기 블로킹 — 이 줄에서 스레드가 멈춘 채 기다린다
PaymentResponse res = restTemplate.postForObject(url, req, PaymentResponse.class);

// 비동기 논블로킹 — 이 줄은 "계획"만 만들고 즉시 반환된다. 아무 일도 안 일어났다
Mono<PaymentResponse> res = webClient.post().retrieve().bodyToMono(PaymentResponse.class);
```

## 트레이드오프

| 동기 블로킹 | 비동기 논블로킹 |
|---|---|
| 스택트레이스가 온전하고 `ThreadLocal`이 따라온다 | 한 요청이 여러 스레드를 오가서 MDC·SecurityContext·트랜잭션 컨텍스트가 안 따라온다 |
| 디버깅이 쉽다 | 적은 스레드로 많은 동시 요청을 버틴다 |

Java 21 가상 스레드([[Java 21 가상 스레드]])는 "동기 블로킹처럼 쓰면서 스레드 점유는 줄인다"로 이 표의 대립을 흐린다.
