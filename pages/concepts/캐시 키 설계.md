## 한 줄 정의

🟡 캐시 키가 잘못되면 **다른 요청이 같은 값을 공유하거나, 같은 요청인데 매번 miss가 난다.** 둘 다 조용히 일어난다.

## 왜 필요한가

`@Cacheable`을 붙였는데 히트율이 0이거나, 반대로 엉뚱한 사용자에게 남의 데이터가 나가는 사고가 여기서 나온다. 🔴 **둘 다 예외를 던지지 않아서 발견이 늦다.**

## 어떻게 동작하는가

`key`를 지정하지 않으면 `SimpleKeyGenerator`가 만든다.

| 파라미터 | 키 |
|---|---|
| 없음 | `SimpleKey.EMPTY` |
| **하나** | **그 파라미터 자체** — `SimpleKey(1L)`이 아니라 `1L` |
| 여러 개 | `SimpleKey [1L, "ko"]` |

`key`를 명시하면 `SimpleKeyGenerator` 대신 **SpEL 평가 결과**가 쓰인다.

## 코드에 닿는 지점

**함정 ① — 파라미터를 흘린다**

```java
@Cacheable(cacheNames = "bookSummary", key = "#id")
public String findBookSummary(long id, String language)
```

```text
findBookSummary(1L, "ko") → key = 1L
findBookSummary(1L, "en") → key = 1L   ← 같은 값을 공유
```

🟢 **의도한 최적화일 수도, 버그일 수도 있다.** 언어별 결과가 달라야 하면 후자다. 키에서 뺀 파라미터가 결과에 영향을 주는지가 판정 기준이다.

**함정 ② — DTO를 키로 쓰는데 `equals`가 없다**

| | 결과 |
|---|---|
| `record` 기반 조건 객체 | 같은 값 → **같은 키** (hit) |
| `equals` 없는 클래스 | 같은 값이어도 **다른 키** (매번 miss) |

🔴 객체 동일성 기준으로 떨어지면 캐시는 있는데 히트율이 0이 된다. → [[equals와 hashCode]]

## 트레이드오프

🔴 **키를 좁히면 공유 사고, 넓히면 히트율 저하.** 파라미터를 전부 키에 넣으면 안전하지만 조합마다 엔트리가 생겨 메모리를 먹는다.

🔴 **SpEL은 컴파일 타임에 안 잡힌다.** 파라미터 이름을 바꾸면 `#id`가 런타임에 깨진다.

🔴 **키에 개인정보를 넣지 않는다.** Redis 키는 `KEYS`/`SCAN`으로 그대로 보인다.
