## 한 줄 정의

🟡 "같은 요청을 두 번 실행해도 안전하다"가 아니라 **"두 번째 실행이 아무 일도 하지 않고 첫 번째와 같은 응답을 돌려준다"**이다.

💬 이 정의 차이가 핵심이다. **예외를 던지면 호출자는 실패로 처리하므로 멱등이 아니다.**

## 왜 필요한가

네트워크 호출의 결과는 셋이다 — 성공 · 실패 · **알 수 없음**. 타임아웃이 났을 때 상대가 처리를 안 한 건지, 처리는 했는데 응답만 못 온 건지 구분할 수 없다.

그래서 재시도해야 하는데, 재시도가 안전하려면 두 번 도착해도 한 번만 반영되어야 한다.

🟡 **재시도는 멱등성 위에서만 안전하다.** 재시도 자체는 실패를 줄이는 장치가 아니라 **실패를 반복하는 장치**이며, 중복 실행을 막는 것은 락과 상태 검사다. 순서를 뒤집어 "재시도를 넣었으니 안전하다"고 생각하면 정확히 그 지점에서 데이터가 두 번 반영된다.

## 어떻게 동작하는가

구현의 축은 두 단계다.

**① 고유 식별자 부여 → ② 상태 검사**

🟢 커머스가 오래 써 온 UI가 이걸 한다. 장바구니와 결제 페이지를 나누는 것은 디자인이 아니라 **식별자 발급 절차**다. "주문하기"가 서버에 주문을 먼저 저장하고 `orderId`를 돌려주며, "결제하기"는 그 `orderId`를 첨부한다. 서버는 이제 두 요청이 같은 주문인지 볼 수 있다.

🟡 식별자 없이는 **검사할 대상 자체가 없다.**

## 코드에 닿는 지점

```java
@Transactional
public ProductReserveResult tryReserve(ProductReserveCommand command) {
    List<ProductReservation> reservations =
            reservationRepository.findAllByRequestId(command.requestId());

    if (!reservations.isEmpty()) {                    // ← 이미 처리한 요청이면
        long totalPrice = reservations.stream()
                .mapToLong(ProductReservation::getPrice).sum();
        return new ProductReserveResult(totalPrice);  //    같은 응답을 그대로 반환
    }
    // ... 예약 수행
}
```

`requestId`에는 `orderId`를 넣는다. 예약/이력 테이블에 `requestId`를 역정규화해 두면 조회 한 번으로 판정이 끝난다.

🟢 Confirm·Cancel도 같다. 이미 `CONFIRMED`면 확정 요청에 아무것도 안 하고 반환하고, 이미 `CANCELED`면 취소 요청을 넘긴다. 상태 전이가 **한 방향**이라 판정이 단순해진다.

## 트레이드오프

🔴 **상태 검사만으로는 동시 중복을 막지 못한다.** 검사와 갱신 사이에 틈이 있는 한, 그 틈에 들어온 요청은 전부 통과한다. 순차 재요청은 막히지만 동시 요청은 그대로 뚫린다.

그래서 [[Redis 분산락]]과 **함께** 써야 한다.

| 장치 | 막는 것 |
|---|---|
| 상태 검사 (멱등성) | **순차** 재요청 |
| 분산락 | **동시** 요청 |

💬 면접에서 "유니크 인덱스를 걸면 됩니다"는 절반만 맞다. **두 번째 요청이 예외로 실패한다면 멱등이 아니다.** 중복 키 예외를 잡아 기존 결과를 조회해 반환하는 데까지 가야 완성이다.

이력을 쌓는 비용도 있다 — 무한히 쌓이므로 보관 기간 정책이 필요하다.

## 실험으로 확인한 것

🟢 [[TCC 실험]]의 `TccSafetyTest`가 상태 로그 없이 깨지는 네 가지를 재현한다.

| 상황 | 로그가 없으면 |
|---|---|
| Confirm 2회 | `reserved_count` 2 → **4. 초과 판매** |
| Cancel 2회 | `held_count` **-2. 재고가 조용히 늘어남** |
| Try 없이 Cancel | 그냥 넘어감 |
| 그 뒤 늦은 Try | 좌석을 잡는데 **아무도 회수 안 함 (매달림)** |

🟡 마지막 두 줄이 한 쌍이다. **빈 취소는 무시가 아니라 기록이어야 한다** — 되돌릴 게 없다고 넘기면 뒤늦은 Try가 잡은 자원이 영영 매달린다.
