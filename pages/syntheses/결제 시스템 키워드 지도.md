## 질문

결제 백엔드에서 알아야 할 키워드는 무엇이고, 각각 위키의 어디에 붙어 있나.

## 답 (짧게)

강의가 키워드를 두 번 뽑아 놨다 — §18에 핵심 25개, §19에 "추가로 학습할 것" 10개. 그중 **20개는 이미 개념 페이지가 있고, 2개는 다른 페이지에 언급만 되어 있고, 13개는 아직 없다.**

🟡 이 지도의 쓸모는 채워진 칸이 아니라 **빈 칸**이다. `[[MOC-결제시스템]]`의 「아직 없는 것」은 3개만 추적하고 있었는데, 키워드 기준으로 훑으니 실제 구멍은 그보다 넓다.

💬 원문의 키워드 표 자체는 `raw/lectures/결제시스템_백엔드_학습가이드.md`의 581행부터에 있다. `raw/`는 gitignore 대상이고 878줄 산문 한가운데라 검색으로 안 잡힌다. 그래서 이 페이지가 필요하다.

## 핵심 키워드 25 (§18)

| 영역 | 키워드 | 결제에서의 쓰임 | 위키 |
|---|---|---|---|
| 메시지 전달 보장 | At-least-once | 최소 한 번은 오되 중복될 수 있다고 가정한다 | [[Kafka 전달 보장]] · [[정확히 한 번 전달의 불가능성]] |
| 중복 처리 방지 | Idempotency Key | 같은 결제 의도를 식별해 재호출이 새 결제를 만들지 않게 한다 | [[멱등성]] |
| 중복 처리 방지 | Inbox / Processed Event | 이미 처리한 `event_id`를 UNIQUE로 기록한다 | [[Inbox 패턴]] |
| DB 방어 | Unique Constraint | 사전 검사를 동시에 통과해도 DB가 마지막에 막는다 | [[멱등성]] 안에 언급만 |
| 상태 관리 | State Machine | 허용 전이를 명시한다 | [[결과 불명 상태]]가 부분 커버 |
| 동시성 제어 | Optimistic Lock / Version | 잔액·완료 플래그의 Lost Update를 감지한다 | [[낙관적 락]] · [[낙관적 락 재시도 경계]] |
| 동시성 제어 | CAS | 예상 상태가 여전히 맞을 때만 갱신한다 | [[조건부 상태 전이 선점]] · [[원자적 UPDATE로 푸는 동시성]] |
| 외부 연동 | Timeout / Deadline | 무한 점유는 막되 결과 불명을 실패로 오판하지 않는다 | [[타임아웃과 데드라인]] |
| 오류 처리 | Error Taxonomy | 영구 거절 · 일시 오류 · 결과 불명을 나눠 다르게 처리한다 | [[오류 분류]] |
| 장애 복구 | Retry / Backoff / Jitter | 일시 장애는 회복하되 재시도 폭풍을 막는다 | [[재시도와 백오프]] |
| 장애 복구 | Retry Budget | 요청 하나와 시스템 전체의 재시도 비용을 제한한다 | [[재시도 예산]] |
| 분산 정합성 | Transactional Outbox | 상태 변경과 이벤트를 같은 로컬 트랜잭션에 기록한다 | [[Outbox 패턴]] · [[Dual Write 문제]] |
| Kafka | Partition Key | 같은 결제의 이벤트를 같은 파티션으로 보내 순서를 지킨다 | [[Kafka 메시지 키와 순서 보장]] |
| Kafka | Consumer Group / Offset | 병렬 처리 단위와 재처리 위치를 관리한다 | [[컨슈머 그룹과 리밸런싱]] |
| Kafka | Kafka Transaction | Kafka 안에서만 원자적. 외부 DB는 안 덮는다 | [[Kafka Transaction의 범위]] |
| 실패 격리 | Retry Topic / DLQ / Parking Lot | 회복 가능하면 지연 재시도, 지속 실패면 격리한다 | [[컨슈머 재시도와 DLQ]] |
| 트랜잭션 | Local Transaction Boundary | 한 DB의 불변식만 짧게 묶고 외부 호출은 상태 전이로 잇는다 | [[업무 트랜잭션과 시스템 트랜잭션]] · [[커밋 후 이벤트 발행]] |
| 회계 | Double-entry Ledger | 금전 이동을 차변·대변 쌍으로 기록한다 | [[복식부기 원장]] |
| 감사 | Append-only | 덮어쓰지 않고 취소·정정 Entry를 추가한다 | [[복식부기 원장]] |
| 복구 | Recovery Worker | 중간 상태에 오래 머문 결제를 최종 상태로 수렴시킨다 | [[복구 워커]] |
| 정합성 검증 | Reconciliation | 내부 DB와 PSP 기록을 비교해 누락·불일치를 찾는다 | [[원장 대사]] |
| 장애 격리 | Bulkhead | 복구·PSP 장애가 정상 결제 자원을 고갈시키지 않게 한다 | [[Bulkhead]] |
| 과부하 제어 | Rate Limit / Backpressure | PSP QPS와 내부 한도에 맞춰 유입량을 제한한다 | [[Rate Limiter]] |
| 관측성 | Correlation ID / Trace | Checkout부터 Ledger까지를 한 흐름으로 추적한다 | [[분산 추적]] |
| 보안 | Secret / PCI DSS / PII | 카드 데이터·개인정보의 저장·로그·접근을 통제한다 | [[결제 데이터 보안]] |

## 추가로 학습할 키워드 10 (§19)

| 키워드 | 왜 필요한가 | 위키 |
|---|---|---|
| Inbox Pattern | Outbox가 Producer 유실을 다룬다면 이쪽은 Consumer 중복을 다룬다 | [[Inbox 패턴]] |
| Saga / Process Manager | 여러 로컬 트랜잭션으로 쪼개진 긴 흐름의 진행 상태를 관리한다 | [[Saga 패턴]] |
| Reconciliation | 온라인 경로가 완벽해 보여도 필요한 최후의 안전망 | [[원장 대사]] |
| Compensation / Reversal Entry | 되돌리기가 아니라 반대 방향 거래를 추가하는 것 | [[환불과 부분 취소]] |
| Refund / Partial Cancel / Chargeback | 승인만 구현하면 결제 시스템의 절반 | [[환불과 부분 취소]] |
| Webhook Verification | Redirect만으로 결과를 확정하지 않는다. 서명·재전송·순서 역전 | [[PSP Webhook 검증]] |
| Circuit Breaker / Rate Limiter | 장애 중인 PSP를 계속 두드리지 않는다 | [[Circuit Breaker]] · [[Rate Limiter]] |
| Schema Evolution | 이벤트 필드가 바뀌어도 구버전 Consumer가 산다 | [[스키마 진화]] |
| Observability와 Audit | UNKNOWN 수 · Outbox 지연 · Consumer Lag · DLQ 증가를 지표로 만든다 | [[분산 추적]] |
| Fault Injection과 통합 테스트 | 정상 경로가 아니라 Commit 전후 Crash Window를 검증한다 | [[장애 주입 테스트]] |

## 아직 페이지가 없는 것

🔴 위 표의 빈 링크가 곧 할 일 목록이다. **8개가 새로 드러났다.**

| 빈 링크 | 왜 비어 있나 |
|---|---|
| [[오류 분류]] | [[재시도와 백오프]]에 "오류 분류"로 스치기만 한다. 영구 거절 / 일시 / 결과 불명 3분류가 독립 개념 |
| [[재시도 예산]] | 완전히 없다. 재시도 폭풍을 막는 축인데 [[재시도와 백오프]]는 개별 호출만 다룬다 |
| [[타임아웃과 데드라인]] | [[결과 불명 상태]]가 결과 해석만 다루고, 시간 예산을 어디서 끊을지는 없다 |
| [[Rate Limiter]] | [[Bulkhead]] 안에 한 줄 언급뿐 |
| [[분산 추적]] | 완전히 없다. [[Micrometer 계측기 선택]]은 지표지 추적이 아니다 |
| [[결제 데이터 보안]] | 완전히 없다. 볼트에 보안 축 자체가 얇다 |
| [[스키마 진화]] | 완전히 없다. Kafka 페이지들이 전달 보장까지만 다룬다 |
| [[장애 주입 테스트]] | 원문 §24의 장애 실험 10종이 그대로 설계서다. `deep-dive/labs/payment-system`에 붙을 자리 |

이미 [[MOC-결제시스템]]이 추적 중이던 것: [[환불과 부분 취소]] · [[PSP Webhook 검증]] · [[Circuit Breaker]].

## 확신도

**높음** — 키워드 목록은 원문 §18·§19를 그대로 옮겼고, 위키 매핑은 `pages/` 전체 grep으로 확인했다. 다만 "부분 커버"로 표시한 두 건(Unique Constraint · State Machine)은 판단이 들어갔다.

## 이 답이 바뀔 조건

- 환불·Webhook·보안 쪽 소스를 ingest하면 빈 링크가 줄어든다
- 🟢 원문 §24의 장애 실험 10종을 `deep-dive/labs/payment-system`에서 돌리면 [[장애 주입 테스트]]가 lab 페이지로 먼저 생길 수 있다 — 이 소스에는 수치가 하나도 없어서 실험이 유일한 숫자 공급원이다
