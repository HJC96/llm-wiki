# 태그 사전

`pages/`의 위키 페이지와 `raw/`의 원본이 **같은 어휘를 쓴다.** 그래야 "이 태그의 원본이 몇 개고 위키 페이지가 몇 개인지"가 한눈에 보인다.

태그는 폴더가 못 하는 일(폴더를 가로지르는 묶기)만 한다. 폴더로 이미 구분되는 걸 태그로 또 만들지 않는다.

## 새 태그를 만드는 기준

**여기 없는 태그가 필요하다고 판단되면 만들어도 된다.** 다만 난립하면 태그가 필터 기능을 잃으므로 아래를 지킨다.

**만들어도 되는 경우**

- **2개 이상의 파일·페이지**에 붙는다 (하나에만 붙을 태그는 만들지 않는다 — 그건 제목이 할 일이다)
- 기존 태그 조합으로 표현하면 의미가 뭉개진다
- 내 스택·관심사에서 앞으로도 반복될 주제다

**만들지 않는 경우**

- 기존 태그로 70% 이상 표현된다 → 기존 것을 쓴다
- 기존 태그의 동의어·표기 변형이다 (`k8s`가 있는데 `kubernetes`)
- 너무 넓거나(`backend`, `개발`) 너무 좁다(`kafka-3.7-consumer-rebalance-bug`)

**표기** — 소문자 kebab-case, 영문 기본(`distributed-transaction`). 한국어가 훨씬 명확한 경우만 한국어.

**절차** — 작업 중에는 새 태그를 그냥 쓰고 멈추지 않는다. 작업이 끝나면 **신규 태그를 한 번에 모아 보고**하고(왜 필요했는지 + 어디에 붙었는지), 승인 후 아래 알맞은 절에 **범위 한 줄과 함께** 등재한다. 마지막에 확인:

```bash
python3 ~/.claude/skills/tag/scripts/tag_tool.py audit   # 사전 밖 태그 색출
python3 ~/.claude/skills/tag/scripts/tag_tool.py vocab   # 사용 빈도. 0회가 많으면 사전이 현실과 겉돈다
```
